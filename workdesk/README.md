# Дело

Личный кабинет для работы с заказами на «Все сдал» и других площадках. Интерфейс размещается на GitHub Pages; аккаунт и записи сохраняются в Supabase. Можно входить с телефона и компьютера одним email и паролем. Подойдет существующий аккаунт личного планировщика.

## Возможности

- Заказы, клиенты, категории, источник, цена, комиссия, срок, статус, ссылка, плановое время и доработки.
- Частичные поступления, предоплата и возвраты. Платежи записываются после удержания комиссии.
- Общие расходы и расходы конкретного заказа.
- Задачи с приоритетом, сроком, связью с заказом и календарь дедлайнов.
- Фактическое время основной работы и доработок.
- Получено, денежный результат, ожидаемая оплата, прибыль завершенных работ и доход за час.
- Сравнение доходности категорий, доля доработок, своевременность первой сдачи, клиенты и загрузка ближайших семи дней.
- Калькулятор цены под желаемый доход за час.
- Цели, свои категории, CSV для Excel и полный экспорт JSON.
- Отдельный вымышленный пример, который не записывается в базу.

## Определения

Получено за месяц = поступления за месяц - возвраты за месяц. Комиссия здесь повторно не вычитается.

Денежный результат = получено - расходы с датой в выбранном месяце.

Прибыль заказа = стоимость - комиссия - все связанные расходы за срок заказа.

Ожидается = неотрицательный остаток суммы после комиссии минус полученные платежи, по всем неотмененным заказам.

Месячный доход за час = денежный результат месяца / все записанные часы месяца. Из-за разных дат работы и оплаты показатель может колебаться; он не заменяет доходность категории.

Доходность категории = прибыль завершенных в выбранном месяце заказов / все часы этих заказов, включая доработки. Общие расходы и налоги в категорию не включены. Заказы без учета времени не позволяют оценить часовую ставку достоверно.

Сдано в срок = доля заказов с первой сдачей в выбранном месяце, у которых дата первой сдачи не позже дедлайна. Факт более поздних доработок остается отдельным параметром.

План загрузки = сумма неотрицательных остатков (плановые часы - фактические часы) по активным заказам со сроком не позже семи дней от сегодняшнего дня, включая просроченные. Значение зависит от полноты внесенных планов.

Все суммы рассчитываются до налогов. Данные площадок вводятся вручную. Интеграции с платежами или «Все сдал» нет.

## Хранение и защита

Таблица `public.workdesk_records` изолирована от таблиц планировщика. RLS ограничивает SELECT/INSERT/UPDATE/DELETE владельцем `auth.uid()`. Неавторизованные и анонимные аккаунты не имеют доступа. Браузер содержит только publishable key, а не серверный ключ. Пароль обрабатывает Supabase Auth. HTML-вывод экранируется, CSP ограничивает ресурсы и сетевые соединения.

Изменения карточек используют оптимистическую проверку версии. Форма не закрывается при неуспешном сохранении. Сервер проверяет принадлежность связанных заказов, баланс платежей и возвратов, сериализует изменения одного аккаунта транзакционной блокировкой и запрещает удаление заказа со связанными записями. Удобный способ убрать работу из активных - статус «Отменен».

Данные загружаются постранично по 1000 записей. Синхронизация при фокусе вкладки и каждые 30 секунд; автоматическая перерисовка не закрывает открытый редактор. Пользовательские записи не сохраняются только в localStorage: источник истины - база. В браузере хранится сессия входа и временно открытая форма. При отсутствии сети запись не считается сохраненной.

JSON - архив всех записей. В этой версии автоматическое восстановление JSON не реализовано. CSV защищает формулы Excel от выполнения пользовательского текста.

## Запуск и проверка

Из корня репозитория `python3 -m http.server 8080`, затем `/workdesk/`.

`node --test workdesk/tests/core.test.mjs` проверяет финансовую логику и даты. `node workdesk/tests/ui.cjs` проверяет интерфейс и сценарии сохранения через изолированную тестовую модель API. Проверка RLS и финансовых ограничений выполняется отдельно в транзакции с откатом, без записи тестовых заказов пользователю.

Supabase JS 2.58.0 поставляется локально, версия закреплена. Лицензия MIT лежит рядом с библиотекой. Внешние CDN при работе не нужны. Шрифт Inter берется из существующего каталога `../fonts/` репозитория, лицензия - `../fonts/OFL.txt`.

В браузерах с WebMCP дополнительно доступны чтение показателей и открытие формы нового заказа. Эти действия используют тот же интерфейс и правила доступа.
